    命令

    命令是与Discord客户端中的应用程序交互的原生方式。有3种类型的命令可在不同的界面中访问：聊天输入 (CHAT_INPUT) 、消息的上下文菜单（右上角菜单或右键点击消息）和用户的上下文菜单（右键点击用户）。

    命令

    命令的命名

    聊天输入命令名称和命令选项名称必须匹配以下正则表达式 ^[-_'\p{L}\p{N}\p{sc=Deva}\p{sc=Thai}]{1,32}$ 并设置Unicode标志。如果使用的任何字母有小写变体，则必须使用小写变体。没有小写变体和/或不区分大小写的字母仍然允许使用。USER 和 MESSAGE 命令可以混合大小写并可以包含空格。

    授权您的应用程序

    命令不依赖于公会中的机器人用户；它们使用 交互 模型。要在公会中创建命令，您的应用程序必须获得 applications.commands 范围的授权，该范围可以单独使用，但也会自动包含在 bot 范围中。

    当请求此范围时，我们“快捷方式”OAuth2 流程，类似于添加机器人。您无需完成流程、交换令牌或任何类似操作。

    如果您的应用程序不需要在服务器中拥有机器人用户即可使其命令生效，则无需在URL中添加机器人范围或权限位字段。

    注册命令

    命令只能通过HTTP端点注册。

    命令可以全局作用域或特定服务器作用域。全局命令适用于所有添加您应用程序的服务器。如果您的应用程序有一个与用户共享共同服务器的机器人，那么该应用程序的单个全局命令也可以在私信中使用。

    服务器命令特定于您在创建时指定的服务器。服务器命令在私信中不可用。在每个作用域（全局和服务器）内，命令名称在每个应用程序、每种类型中都是唯一的。这意味着：

    • 您的应用程序不能有两个同名的全局CHAT_INPUT命令
    • 您的应用程序不能在同一个服务器中有两个同名的服务器CHAT_INPUT命令
    • 您的应用程序不能有两个同名的全局USER命令
    • 您的应用程序可以有一个同名的全局和服务器CHAT_INPUT命令
    • 您的应用程序可以有一个同名的全局CHAT_INPUT和USER命令
    • 您的应用程序不能有一个PRIMARY_ENTRY_POINT服务器命令
    • 多个应用程序可以有同名命令

    此列表并非详尽无遗。总的来说，请记住命令名称必须在每个应用程序、每种类型以及每个作用域（全局和服务器）内保持唯一。

    一个应用程序可以拥有以下数量的命令：

    • 100个全局CHAT_INPUT命令
    • 5个全局USER命令
    • 5个全局MESSAGE命令
    • 1个全局PRIMARY_ENTRY_POINT命令

    对于除PRIMARY_ENTRY_POINT之外的所有命令类型，每个服务器您可以拥有相同数量的服务器特定命令。

    每个服务器每天有200个应用程序命令创建的全局速率限制。

    创建服务器命令

    服务器命令仅在创建时指定的服务器中可用。服务器命令会立即更新。我们建议您使用服务器命令进行快速测试，并在准备好公开发布时使用全局命令。

    要创建服务器命令，请执行类似的HTTP POST调用，但将其作用域设置为特定的guild_id：

headers = {

    更新和删除命令

    命令可以通过向命令端点发出 DELETE 和 PATCH 请求来删除和更新。这些端点是

    • 全局命令的端点是 applications/<my_application_id>/commands/<command_id>，或者
    • 服务器命令的端点是 applications/<my_application_id>/guilds/<guild_id>/commands/<command_id>

    由于命令在类型和范围中具有唯一名称，因此我们将新命令的 POST 请求视为 upsert（存在则更新，不存在则创建）。这意味着使用已用于您的应用程序的名称创建新命令将更新现有命令。

    有关应用程序命令端点及其参数的详细文档请参阅端点部分。

    上下文

    命令在应用程序命令对象上有两组上下文，它们允许您配置何时何地可以使用它：

    • integration_types 定义命令支持的安装上下文
    • contexts 定义命令可以在其中使用的交互上下文

    两种命令上下文的详细信息都在下面的部分中。

    上下文与安装到服务器的应用程序的任何命令权限不同，并且不影响它们。

    安装上下文

    安装上下文是您的应用程序安装的位置——到服务器、用户或两者。如果您的应用程序支持两种安装上下文，则在某些情况下，您可能希望您的应用程序的某些命令仅对其中一种可用。例如，您的应用程序可能有一个 /profile 命令，该命令仅在安装到用户时才相关。

    只要任何包含的上下文已经在应用程序级别支持，就可以在使用integration_types字段创建或更新命令时设置命令支持的安装上下文。

    命令的 integration_types 值可能会影响命令在哪些交互上下文中可见。

    交互上下文

    命令的交互上下文决定了它可以在 Discord 客户端的何处使用，并且可以在创建或更新命令时通过设置contexts字段来配置。

    有三种交互上下文类型对应于不同的界面：GUILD (0)、BOT_DM (1) 和 PRIVATE_CHANNEL (2)。然而，PRIVATE_CHANNEL 交互上下文仅对安装到用户的命令有意义（当命令的 integration_types 包含 USER_INSTALL 时）。

    权限

    应用程序命令权限允许您的应用程序在服务器内为最多 100 个用户、角色和频道启用或禁用命令。如果用户拥有必要的权限，他们还可以在客户端中更新命令权限。

    命令权限只能使用 Bearer token 进行更新。使用 bot token 进行身份验证将导致错误。

    可以使用 GET /applications/{application.id}/guilds/{guild.id}/commands/{command.id}/permissions 端点检索命令的当前权限。响应将包含一个名为 permissions 的数组，其中包含关联的 ID 和权限类型。

    命令权限可以使用PUT /applications/{application.id}/guilds/{guild.id}/commands/{command.id}/permissions端点进行更新。要调用此端点，应用必须使用一个Bearer令牌，该令牌通过applications.commands.permissions.update作用域授权给一个拥有足够权限的用户。为了使其权限被视为足够，对于认证用户（而不是您的应用或机器人用户），以下所有条件都必须为真：

    • 在正在编辑命令的服务器中，拥有管理服务器和管理角色的权限
    • 能够运行正在编辑的命令
    • 拥有管理将受影响资源的权限（角色、用户和/或频道，取决于权限类型）

    同步和取消同步权限

    可以通过导航至服务器设置 > 集成，然后点击已安装应用右侧的管理来访问客户端中的命令权限界面。在该界面的顶部，用户可以编辑特定用户、角色或频道的权限。默认情况下，这些顶级权限将应用于应用的所有命令。然而，每个权限也可以取消同步并为单个命令进行自定义，以提供更精细的控制。

    当特定命令的权限未同步，即与顶级权限不一致时，界面将向用户显示“未同步”。

    使用默认权限

    可以在创建命令时使用default_member_permissions和context字段添加默认权限。添加默认权限不需要任何Bearer令牌，因为它在命令创建期间配置，并不针对特定角色、用户或频道。

    子命令和子命令组

    目前，子命令和子命令组都会出现在命令资源管理器的顶层。未来可能会有所改变，将它们作为嵌套的自动完成选项包含在内。

    对于那些希望创建更有组织和更复杂命令组的开发者来说，子命令和组是不二之选。

    子命令通过在命令或组内指定操作来组织您的命令。

    子命令组通过在命令内按相似操作或资源对子命令进行分组来组织您的子命令。

    这些并非强制规则。您可以自由使用子命令和组；这只是我们的思考方式。

    使用子命令或子命令组将使您的基础命令无法使用。如果您同时拥有作为子命令或子命令组的/permissions add | remove，则无法将基础/permissions命令作为有效命令发送。

    入口点命令

    入口点命令是用户从应用启动器打开应用活动的主要方式。

    要使入口点命令对用户可见，应用必须启用活动。

    示例入口点命令
    {
　　　　"name": "launch",
　　　　"description": "启动与朋友赛车",
　　　　"type": 4,
　　　　"handler": 2
}

    入口点处理程序

    当用户调用应用的入口点命令时，handler的值将决定如何处理交互：

    • 对于APP_HANDLER(1)，应用负责响应交互。它可以通过使用LAUNCH_ACTIVITY(类型12)交互回调类型启动应用关联的活动来响应，或采取其他操作(如在频道中发送跟进消息)。
    • 对于DISCORD_LAUNCH_ACTIVITY(2)，Discord将自动处理交互，启动关联的活动并向启动的频道发送消息。

    默认入口点命令

    当您启用活动功能时，系统会自动为您的应用创建一个名为"启动"的入口点命令，并将DISCORD_LAUNCH_ACTIVITY(2)设置为入口点处理程序。您可以通过调用获取全局命令端点并查找"启动"命令，来获取自动创建命令的详细信息（如ID）。

    有关更新或替换默认入口点命令的详细信息，请参阅设置入口点命令指南。

    自动补全

    自动补全交互允许您的应用在用户输入时动态返回选项建议。

    自动补全交互可以返回选项值的部分数据。只要用户输入通过客户端验证，您的应用就会收到任何现有用户输入的部分数据。例如，您可能会收到部分字符串，但不会收到无效数字。用户当前正在输入的选项将附带focused: true布尔字段发送，而用户已填写的选项也会发送，但不带focused字段。这是一种特殊情况，由于用户尚未填写，原本必需的选项可能不会出现。

    本地化

    命令可以进行本地化，这将根据客户端选择的语言使用本地化的名称和描述。这完全是可选的。通过在创建或更新命令时提交相应的name_localizations和description_localizations字段，可以对命令、子命令和选项的名称和描述以及选项选择的名称进行本地化。

    命令可以部分本地化——不需要支持所有可用区域设置，命令中的不同字段也不需要支持相同的区域设置集。如果某个字段的本地化字典中不存在某个区域设置，则该区域设置的用户将看到该字段的默认值。不需要用默认值填充所有区域设置。任何与默认值相同的本地化值都将被忽略。

    本地化的选项名称受到额外约束，即它们必须与该命令的所有其他默认选项名称以及该命令上该区域设置的所有其他选项名称不同。

    当利用命令本地化时，客户端接收的交互负载仍将使用默认的命令、子命令和选项名称。要本地化您的交互响应，您可以通过交互负载中的locale键来确定客户端选择的语言。

    一个带有本地化信息的命令可能如下所示：

    区域设置回退

    对于命令，如果用户的区域设置不在本地化中，有内置的回退机制。如果回退区域设置也缺失，将使用默认值。

    您应确保在适当的区域设置键中包含默认值，否则可能会意外使用回退值。例如，如果您的默认值是 en-US，但您未在本地化中指定 en-US 值，则选择 en-US 的用户将看到指定的 en-GB 值。例如，如果您有一个默认名称为"color"的命令，而您的本地化仅指定 en-GB 值为 "colour"，则 en-US 区域的用户将看到 "colour"，因为缺少 en-US 键。

    区域设置回退
    en-USen-GB
    en-GBen-US
    es-419es-ES

    获取本地化命令

    虽然大多数返回命令对象的端点会返回 name_localizations 和 description_localizations 字段，但有些端点默认不会返回。这包括返回应用所有公会或全局命令的 GET 端点。相反，这些端点将提供额外的 name_localized 或 description_localized 字段，这些字段仅包含与请求者区域设置相关的本地化内容。（完整的字典仍可通过提供适当的查询参数获得）。

　　"description": "Wish a friend a happy birthday",
　　"name_localized": "生日",

　　"options": [
　　　　{
　　　　　　"name": "age",
　　　　　　"type": 4,
　　　　　　"description": "Your friend's age",
　　　　　　"name_localized": "岁数",
　　　　　　"description_localized": "你朋友的岁数",

    年龄限制命令

    包含年龄限制内容的命令应在创建或更新时将 nsfw 字段设置为 true。将命令标记为年龄限制将限制谁可以看到和访问该命令，以及从哪些频道访问。

    启用发现功能的应用（这是出现在应用目录中的必要条件）不能包含任何年龄限制命令或内容。

    使用年龄限制命令

    要使用年龄限制命令，用户必须年满18岁或以上，并从以下任一位置访问该命令：

    • 一个年龄限制频道或
    • 在用户设置中启用年龄限制命令后，与应用的私信。

    有关访问和使用年龄限制命令的详细信息，请参见帮助中心。

    PUT/applications/{application.id}/guilds/{guild.id}/commands/{command.id}/permissions 此端点将覆盖该公会中命令的现有权限

    编辑应用程序在公会中特定命令的权限，并返回一个公会命令权限对象。触发命令权限更新网关事件。

    您可以为命令添加最多100个权限覆盖。

    此端点需要使用具有管理公会及其角色权限的Bearer令牌进行身份验证。有关更多信息，请阅读上面关于命令权限的内容。删除或重命名命令将永久删除该命令的所有权限

    JSON参数
    字段类型描述
    permissions命令权限数组命令在公会中的权限

    批量编辑命令权限

    PUT/applications/{application.id}/guilds/{guild.id}/commands/permissions 此端点已随命令权限更新（权限v2）而禁用。相反，您可以单独编辑每个命令权限（但应注意处理可能的速率限制）。
