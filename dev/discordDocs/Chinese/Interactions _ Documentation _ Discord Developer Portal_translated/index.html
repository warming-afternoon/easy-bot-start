    Interactions Documentation Discord Developer Portal translated

    交互是指当用户使用应用命令或消息组件时，您的应用接收到的消息。

    对于斜杠命令，它包含用户提交的值。

    对于用户命令和消息命令，它包含执行操作时解析出的用户或消息。

    对于消息组件，它包含已使用组件的标识信息。它还将包含有关交互触发方式的一些元数据：guild_id、channel、member和其他字段。您可以在下面的数据模型中找到所有值。

    交互上下文类型

    交互在Discord中可使用或触发的上下文环境。关于应用命令使用交互上下文的详细信息请参阅命令上下文文档。

    名称类型说明
    GUILD0交互可在服务器内使用
    BOT_DM1交互可在与应用机器人用户的私信中使用
    PRIVATE_CHANNEL2交互可在群组私信及非机器人用户私信中使用

    authorizing_integration_owners字段包含与交互相关的安装授权用户或服务器的详细信息。对于安装到用户的应用，可用于区分授权用户和触发交互的用户（如消息组件）。

    仅当满足以下条件时才会出现对应键名：

    • 应用已获得与键名对应的安装上下文授权（GUILD_INSTALL或USER_INSTALL）
    • 交互在键名对应安装上下文的源交互上下文（GUILD、BOT_DM或PRIVATE_CHANNEL）中受支持
    • 对于命令调用，该命令必须在安装上下文中受支持（使用integration_types）

    authorizing_integration_owners中的取值取决于键名——

    • 若键名为GUILD_INSTALL（"0"），其值取决于交互来源： 　　　　* 若交互从服务器触发，其值为服务器ID 　　　　* 若交互从与应用机器人用户的私信触发，其值为"0"
    • 若键名为USER_INSTALL（"1"），其值为授权用户的ID

    接收交互

    当用户与您的应用交互时，您的应用将收到一个交互。您的应用可以通过以下两种方式之一接收交互：

    • 通过交互创建网关事件
    • 通过出站webhook

    这两种方法是互斥的；您只能通过其中一种方式接收交互。INTERACTION_CREATE网关事件可由连接的客户端处理，而下面详述的webhook方法不需要连接的客户端。

    如果您想通过基于HTTP的出站webhook接收交互，必须为您的应用配置交互端点URL。您可以在交互概览的准备交互部分阅读有关准备和添加交互端点URL到您的应用的信息。

    交互元数据

    一个交互包含元数据以帮助您的应用程序处理它，以及特定于交互类型的data。您可以在各自的页面上找到每种交互类型的示例：

    现在您已经从用户那里获取了数据，是时候回应他们了。

    回应交互

    交互——无论是接收还是回应——本质上都是webhook。因此，回应交互就像发送webhook请求一样！

    交互回应具有与普通HTTP API请求相同的头部要求。有关更多信息，请参见此处。

    您可以通过多种方式回应交互：

    交互回调

    当响应接收到的交互时，您可以向/interactions/<interaction_id>/<interaction_token>/callback发送POST请求。interaction_id是接收到的负载中该特定交互的唯一ID。interaction_token是接收到的负载中该交互的唯一令牌。

    如果您通过网关接收交互，必须通过HTTP进行响应。对交互的响应不会作为命令通过网关发送。

    如果您对通过HTTP接收的交互发送此请求，请用202状态码和无正文响应原始HTTP请求。

    导入请求

网址 = "https://discord.com/api/v10/interactions/<交互ID>/<交互令牌>/callback"

JSON = {
　　　　"类型": 4,
　　　　"数据": {
　　　　　　　　"内容": "恭喜发送命令！"
　　　　}
}
r = requests.post(网址, json=json)

    交互令牌有效期为15分钟，可用于发送后续消息，但必须在接收事件后3秒内发送初始响应。如果超过3秒期限，令牌将失效。

    后续消息

    有时，您的机器人在响应交互后希望向用户发送后续消息。或者，您可能想要编辑原始响应。无论您是通过网关接收交互还是通过出站webhook，都可以使用以下端点来编辑初始响应或发送后续消息：

    • PATCH /webhooks/<application_id>/<interaction_token>/messages/@original 用于编辑对交互的初始响应
    • DELETE /webhooks/<application_id>/<interaction_token>/messages/@original 用于删除对交互的初始响应
    • POST /webhooks/<application_id>/<interaction_token> 用于发送新的后续消息
    • PATCH /webhooks/<application_id>/<interaction_token>/messages/<message_id> 用于编辑使用该 token 发送的消息

    交互webhook与普通webhook共享相同的速率限制属性。

    交互令牌有效期为15分钟，这意味着您可以在该时间段内响应交互。

    创建后续消息

    如果交互是由用户安装的应用发起且未在服务器中安装（即授权集成所有者对象仅包含USER_INSTALL），则每个交互的应用限制为5条后续消息。

    为交互创建后续消息。功能与执行Webhook相同，但wait始终为true。使用此端点进行交互后续操作时，不支持thread_id、avatar_url和username参数。可以使用EPHEMERAL消息标志1 << 6（64）发送仅用户可见的消息。也可以使用IS_COMPONENTS_V2消息标志1 << 15（32768）发送基于组件的消息。

    在使用DEFERRED_CHANNEL_MESSAGE_WITH_SOURCE响应交互后直接使用此端点时，出于向后兼容性考虑，此端点将作为编辑原始交互响应功能。在这种情况下，不会创建新消息，而是编辑加载消息。临时标志将被忽略，初始延迟响应中提供的值将被保留，因为现有消息的临时状态无法更改。此行为已弃用，在这种情况下应使用编辑原始交互响应端点。
