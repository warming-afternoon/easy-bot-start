    接收及响应

    当用户使用应用命令或消息组件时，交互就是您的应用程序接收到的消息。

    对于斜杠命令，它包含用户提交的值。

    对于用户命令和消息命令，它包含执行操作时解析出的用户或消息。

    对于消息组件，它包含有关所使用组件的标识信息。它还将包含有关交互触发方式的一些元数据：guild_id、channel、member 和其他字段。您可以在下面的数据模型中查找所有值。

    交互对象

    交互结构

    application_id雪花ID此交互所属应用的ID
    type交互类型交互的类型
    data?*交互数据交互数据负载
    guild?部分服务器对象交互发送来源的服务器
    guild_id?雪花ID交互发送来源的服务器ID

    channel_id?雪花ID交互发送来源的频道ID
    member?**服务器成员对象调用用户的服务器成员数据，包括权限
    user?用户对象如果在私信中调用，则为调用用户的用户对象
    token字符串用于响应交互的续传令牌
    version整数只读属性，始终为1
    message?消息对象对于由组件触发的组件或模态框，它们所附加的消息

    authorizing_integration_owners以应用集成类型为键的字典交互被授权安装的上下文映射到相关用户或服务器ID。详情参见授权集成所有者对象

    * : 该字段始终存在于应用命令、消息组件和模态提交交互类型中。为面向未来兼容新交互类型，该字段为可选

    ** : 当交互在服务器中调用时发送 member，在私信（DM）中调用时发送 user

    *** : app_permissions 包含与其他用户的（群组）私信中的 ATTACH_FILES | EMBED_LINKS | MENTION_EVERYONE 权限，在与应用机器人用户的私信中额外包含 USE_EXTERNAL_EMOJIS

    **** : 该字段在除 PING 外的所有交互类型中可用

    交互上下文类型

    Discord 中可使用交互或触发交互的上下文。有关应用命令使用交互上下文的详细信息，请参阅命令上下文文档。

    名称类型描述
    GUILD0交互可在服务器内使用
    BOT_DM1交互可在与应用机器人用户的私信中使用
    PRIVATE_CHANNEL2交互可在群组私信和除应用机器人用户外的私信中使用

    authorizing_integration_owners 字段包含与交互相关的安装授权用户或服务器的详细信息。对于安装到用户的应用，可用于区分授权用户和触发交互的用户（如消息组件）。

    仅当以下条件满足时才会存在键：

    • 应用已获得与键对应的安装上下文授权（GUILD_INSTALL 或 USER_INSTALL）
    • 交互在键对应安装上下文的源交互上下文（GUILD、BOT_DM 或 PRIVATE_CHANNEL）中受支持
    • 对于命令调用，命令必须在安装上下文中受支持（使用 integration_types）

    authorizing_integration_owners 中的值取决于键——

    • 如果键是 GUILD_INSTALL（"0"），值取决于交互来源：
      　* 如果交互从服务器触发，值将为服务器ID
      　* 如果交互从与应用机器人用户的私信触发，值将为 "0"
    • 如果键是 USER_INSTALL（"1"），值将为授权用户的ID

    应用命令交互数据选项结构

    所有选项都有名称，选项可以是参数和输入值——此时将设置value——或者可以表示子命令或组——此时它将包含一个顶级键和另一个options数组。

    value和options是互斥的。

    字段类型描述
    name字符串参数的名称
    type整数应用命令选项类型的值
    value?字符串、整数、双精度或布尔值用户输入产生的选项值
    options?应用命令交互数据选项的数组如果此选项是组或子命令，则存在
    focused?布尔值如果此选项是自动补全当前聚焦的选项，则为true

    接收交互

    当用户与您的应用交互时，您的应用将收到一个交互。您的应用可以通过以下两种方式之一接收交互：

    • 通过交互创建网关事件
    • 通过传出webhook

    这两种方法是互斥的；您只能通过其中一种方式接收交互。INTERACTION_CREATE网关事件可以由连接的客户端处理，而下面详述的webhook方法不需要连接的客户端。

    如果您想通过基于HTTP的传出webhook接收交互，您必须为您的应用配置一个交互端点URL。您可以在交互概述的准备交互部分阅读有关准备和添加交互端点URL到您的应用的信息。

    交互元数据

    一个交互包括元数据以帮助您的应用程序处理它，以及特定于交互类型的data。您可以在各自的页面上找到每种交互类型的示例：

    • 斜杠命令
    • 用户命令
    • 消息命令
    • 消息组件
    • 模态组件

    所有字段的解释可以在我们的数据模型中找到。

    既然您已经从用户那里获取了数据，是时候回应他们了。

    回应交互

    交互——无论是接收还是回应——本质上都是webhook。因此，回应交互就像发送webhook请求一样！

    交互响应具有与普通HTTP API请求相同的头部要求。更多信息请参见此处。

    您可以通过多种方式回应交互：

    交互响应对象

    交互响应结构
    字段类型描述
    type交互回调类型响应类型
    data?交互回调数据可选的响应消息
    交互回调类型
    名称值描述
    PONG1确认Ping请求
    CHANNEL_MESSAGE_WITH_SOURCE4用消息响应交互
    DEFERRED_CHANNEL_MESSAGE_WITH_SOURCE5确认交互并稍后编辑响应，用户会看到加载状态
    DEFERRED_UPDATE_MESSAGE*6对于组件，确认交互并稍后编辑原始消息；用户不会看到加载状态
    UPDATE_MESSAGE*7对于组件，编辑组件所附加的消息
    APPLICATION_COMMAND_AUTOCOMPLETE_RESULT8用建议选项响应自动补全交互
    MODAL**9用弹出模态框响应交互
    PREMIUM_REQUIRED10已弃用；用升级按钮响应交互，仅适用于启用货币化的应用
    LAUNCH_ACTIVITY12启动与应用关联的活动。仅适用于启用活动的应用

    * : 仅对基于组件的交互有效

    ** : 不适用于MODAL_SUBMIT和PING交互

    消息

    并非所有消息字段目前都被支持

    字段类型描述

    embeds?嵌入数组最多支持10个嵌入
    allowed_mentions?允许提及允许提及对象

    字段类型描述

    模态框
    字段类型描述

    交互回调

    当响应接收到的交互时，您可以向/interactions/<interaction_id>/<interaction_token>/callback发起POST请求。interaction_id是接收到的有效载荷中该特定交互的唯一ID。interaction_token是接收到的有效载荷中该交互的唯一令牌。

    如果您通过网关接收交互，必须通过HTTP进行响应。对交互的响应不会作为命令通过网关发送。

    如果您针对通过HTTP接收的交互发送此请求，请以202状态码且无正文响应对原始HTTP请求。

    导入请求库

网址 = "https://discord.com/api/v10/interactions/<交互ID>/<交互令牌>/callback"

数据 = {
　　　　"类型": 4,
　　　　"数据": {
　　　　　　　　"内容": "恭喜发送命令！"
　　　　}
}
响应 = requests.post(网址, json=数据)

    交互令牌有效期为15分钟，可用于发送后续消息，但必须在收到事件后3秒内发送初始响应。如果超过3秒期限，令牌将失效。

    后续消息

    有时，您的机器人在响应交互后需要向用户发送后续消息。或者，您可能想要编辑原始响应。无论您是通过网关还是通过出站webhook接收交互，都可以使用以下端点编辑初始响应或发送后续消息：

    • PATCH /webhooks/<application_id>/<interaction_token>/messages/@original 编辑对交互的初始响应
    • DELETE /webhooks/<application_id>/<interaction_token>/messages/@original 删除对交互的初始响应
    • POST /webhooks/<application_id>/<interaction_token> 发送新的后续消息
    • PATCH /webhooks/<application_id>/<interaction_token>/messages/<message_id> 编辑使用该token发送的消息

    交互webhook与普通webhook共享相同的速率限制属性。

    交互令牌有效期为15分钟，意味着您可以在该时间内响应交互。

    端点

    创建交互响应

    此端点还支持类似于webhook端点的文件附件功能。有关上传文件和multipart/form-data请求的详细信息，请参阅文件上传。

    查询字符串参数
    字段类型描述

    获取原始交互响应

    返回初始的交互响应。功能与获取Webhook消息相同。

    编辑原始交互响应

    编辑初始的交互响应。功能与编辑Webhook消息相同。

    删除原始交互响应

    删除初始的交互响应。成功时返回204 No Content。

    创建后续消息

    如果交互是由用户安装的应用发起且未在服务器中安装（即授权集成所有者对象仅包含USER_INSTALL），则每个交互的应用限制为5条后续消息。

    为交互创建后续消息。功能与执行Webhook相同，但wait始终为true。使用此端点进行交互后续消息时，不支持thread_id、avatar_url和username参数。您可以使用EPHEMERAL消息标志1 << 6（64）发送仅用户可见的消息。您也可以使用IS_COMPONENTS_V2消息标志1 << 15（32768）发送基于组件的消息。

    在响应交互后立即使用DEFERRED_CHANNEL_MESSAGE_WITH_SOURCE时，此端点将作为编辑原始交互响应以实现向后兼容性。在这种情况下，不会创建新消息，而是编辑加载消息。临时标志将被忽略，初始延迟响应中提供的值将被保留，因为现有消息的临时状态无法更改。此行为已弃用，您应在此情况下使用编辑原始交互响应端点。

    获取后续消息

    返回交互的后续消息。功能与获取Webhook消息相同。

    编辑后续消息

    编辑交互的后续消息。功能与编辑Webhook消息相同。

    删除后续消息

    删除交互的后续消息。成功时返回204 No Content。
